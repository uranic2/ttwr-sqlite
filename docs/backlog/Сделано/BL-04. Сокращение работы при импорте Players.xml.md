# BL-04. Сокращение работы при импорте Players.xml — P2

**Статус: выполнено в 0.1.7.** Один SAX-проход без DOM, индексы после загрузки, замеры на 150 тысячах синтетических игроков. Описание ниже сохраняет исходную постановку задачи.

**Наблюдение.** Полного DOM списка уже нет. Однако XML разбирается дважды: сначала для проверки и подсчёта, затем для импорта. Для каждой записи создаётся небольшое DOM-дерево; при вставке обновляются восемь вторичных индексов.

**Пользовательский сценарий.** Обновление большого списка требует повторной обработки XML и дополнительных операций записи во временную SQLite-базу.

**Предложение.** Измерить пользу однопроходного импорта во временную БД, прямого разбора полей без DOM и создания вторичных индексов после загрузки. Для однопроходной загрузки пересмотреть отображение прогресса: точное количество записей заранее неизвестно.

**Обязательные условия.** Сохранить совместимость XML, проверку целостности, отмену и замену рабочей БД только после полного успеха. Ошибочный XML не должен повреждать действующий список.

**Критерий проверки.** Содержимое БД совпадает с результатом текущего импортера, включая Unicode и особые значения рейтинга. Сравнить время, пик памяти и объём записи на большом XML; проверить ошибку в конце документа и отмену.

Код: [StreamingPlayers.java](../../../src/main/java/ttr/StreamingPlayers.java), `loadInto()`, `Builder`; [SqlitePlayersIntegration.java](../../../src/main/java/ttr/SqlitePlayersIntegration.java), `importXml()`; [SqlitePlayersStore.java](../../../src/main/java/ttr/SqlitePlayersStore.java), создание индексов.
