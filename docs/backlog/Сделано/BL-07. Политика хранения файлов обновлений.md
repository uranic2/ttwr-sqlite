# BL-07. Политика хранения файлов обновлений — P2

**Статус: выполнено в 0.1.7, проверка полного комплекта исправлена в 0.1.8.** [Шесть реальных переходов](../../validation/Обновление-до-0.1.8.md) подтвердили очистку и сохранность данных. [Реальное обновление](../../validation/Обновление-0.1.6-до-0.1.7.md) выявило ошибку проверки резервной копии исходной установки со встроенной Java: данные сохраняются, но старые обновления не очищаются. В 0.1.8 проверка резервной копии учитывает сохраняемую на месте Java и продолжает проверять все файлы приложения по SHA-256.

Автоматическая очистка старых проверенных успешных установок после старта с сохранением последней пригодной копии; добавлен просмотр объёма. Описание ниже сохраняет исходную постановку задачи.

**Наблюдение.** После успешной установки сохраняются загруженный ZIP, распакованный комплект, помощник и резервная копия старой программы. Политики очистки успешных обновлений нет.

**Пользовательский сценарий.** После нескольких обновлений растёт объём `data/updates`.

**Предложение.** Сохранять последнюю пригодную резервную копию, показывать занимаемый объём и очищать более старые комплекты после подтверждённого успешного запуска. Определить, какие журналы и копии нужны для восстановления. Не очищать выполняющееся или неудачное обновление без явного правила.

**Критерий проверки.** Последняя резервная копия остаётся пригодной для восстановления. Рабочие БД, настройки, турниры, `runtime` и посторонние файлы не удаляются; ссылки за пределы допустимого каталога не обходятся.

Код: [ProgramUpdates.java](../../../src/main/java/ttr/updates/ProgramUpdates.java), `download()`, `discard()`; [UpdateInstaller.java](../../../src/main/java/ttr/updates/UpdateInstaller.java).
