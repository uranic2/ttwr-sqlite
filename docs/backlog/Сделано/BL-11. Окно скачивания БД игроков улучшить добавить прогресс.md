# BL-11. Прогресс загрузки и обновления БД игроков — P2

**Статус: реализовано в 0.1.10.**

Совместно с BL-13 используются общее окно, отмена, резервирование и журнал восстановления. [Результаты проверок](../../validation/Проверка-BL-11-и-BL-13.md). Ниже сохранена исходная постановка; описание прежней реализации относится к моменту её составления.

## Цель

Улучшить окно штатного обновления списка игроков: пользователь должен видеть текущий этап, объём полученных данных, скорость, прошедшее время и доступную оценку оставшегося. Должна быть понятная возможность отменить операцию с сохранением прежней рабочей базы.

По оформлению и правилам обновления показателей ориентироваться на окно загрузки обновления программы из 0.1.9: **обновление раз в секунду**, текущая скорость **за последние 2 секунды**.

## Особенность текущей реализации

`StreamingPlayers` читает `Players.xml` по сети и разбирает его одним SAX-проходом. Записи сразу поступают во временную SQLite-базу. Затем создаются индексы, проверяется целостность и результат применяется к рабочей базе.

Поэтому окончание получения XML не означает завершение всего обновления. На скорость чтения потока могут влиять разбор XML и запись SQLite: отображаемое значение характеризует текущую обработку потока, а не отдельный замер пропускной способности интернета.

В коде уже есть уведомления о прочитанных байтах и этапах. Счётчик записей в действующем загрузчике передаётся после окончания разбора; для отображения текущего количества его потребуется обновлять во время обработки.

## Что показывать

| Показатель | Требование |
|---|---|
| Текущий этап | Понятное название: соединение, загрузка и импорт XML, создание индексов, проверка базы, применение обновления |
| Объём | Получено / всего в КБ; 1 КБ = 1024 байта |
| Процент | Только для этапа чтения XML и только при достоверно известном общем размере |
| Текущая скорость | Средняя скорость чтения за последние 2 секунды, КБ/с; в начале — за доступный интервал |
| Средняя скорость | Полученный объём / время этапа загрузки, КБ/с |
| Записи | «Прочитано записей: N»; после успеха отдельно показать итоговое число игроков в базе |
| Прошедшее время | Секунды с начала всей операции обновления |
| Оставшееся время | Приблизительное время до окончания чтения XML по оставшимся байтам и текущей скорости |

Показатели обновляются раз в секунду. Расчёты времени выполняются по монотонным часам. Отсутствующие значения обозначаются «—»; деление на ноль, отрицательные скорости и отрицательное оставшееся время недопустимы.

Для записей нельзя заранее показывать неизвестное общее количество. Не добавлять повторный проход по XML или загрузку всего списка в память ради знаменателя прогресса. Число прочитанных записей и итоговое число уникальных игроков могут различаться, например при повторяющихся ID; подписи должны отражать это различие.

## Этапы и состояния окна

1. **Соединение.** Показать состояние подключения, прошедшее время и доступную отмену. До получения данных объём равен нулю, скорость и оценка времени ещё не определены.
2. **Загрузка и импорт XML.** При известном размере показать полосу с процентом и полученный / общий объём. Счётчик записей увеличивается по мере разбора. Ввод и импорт остаются одним потоковым конвейером.
3. **Неизвестный размер.** Если сервер не сообщил достоверный размер, использовать неопределённую полосу: «Получено X КБ; общий объём неизвестен». Скорости и прошедшее время доступны, процент и оценка оставшегося — «—».
4. **Создание индексов и проверка.** После чтения XML переключить название этапа и полосу на неопределённый режим, если точный прогресс этого этапа недоступен. Сетевую скорость и оценку окончания чтения больше не показывать как текущие; сохранить итоговый объём и среднюю скорость загрузки. Прошедшее время всей операции продолжает увеличиваться.
5. **Применение обновления.** Показать отдельное состояние. Для короткой критической операции переключения на готовую базу отмена может временно стать недоступной с подписью «Завершаем обновление…». До этой границы отмена должна сохранять прежнюю рабочую базу.
6. **Успех.** Сообщить о завершении только после успешной проверки, применения базы и обновления списка в интерфейсе. Показать итоговое число игроков и затраченное время.

Не показывать выдуманный общий процент по всем этапам. Даже «100%» прочитанного XML не должно сопровождаться сообщением «База обновлена», пока продолжаются создание индексов или применение результата.

## Расположение элементов

- Вверху — заголовок «Обновление списка игроков» и текущий этап.
- Ниже — полоса прогресса и объём данных.
- Следующей строкой — текущая и средняя скорости в двух выровненных столбцах.
- Затем — количество прочитанных записей, прошедшее время и доступная оценка окончания чтения XML.
- Внизу — кнопка **«Отмена»**; при завершении — доступное действие закрытия окна по принятому в программе сценарию.

Числа должны быть читаемыми, подписи — оставаться на месте при изменении значений. Окно должно корректно отображаться с принятым в программе масштабом шрифта.

## Отмена и ошибки

Кнопка «Отмена», Esc и крестик окна должны использовать единый сценарий отмены, пока она доступна:

1. Показать «Отмена обновления…» и исключить повторный запуск той же операции.
2. Прервать сетевое чтение и обработку временной базы без блокировки потока интерфейса. Проверить отмену также во время создания индексов и других длительных SQL-операций.
3. Дождаться закрытия потоков, отмены незавершённых транзакций и закрытия временных подключений.
4. Удалить только временные файлы текущей операции и оставить прежнюю рабочую базу активной.
5. После завершения очистки разрешить повторную попытку обновления.

Не удалять рабочие `Players.sqlite`, WAL/SHM, настройки, турниры и существующие резервные копии. Очистка временных файлов не должна обходить ссылки за пределы допустимых каталогов. Если очистка не удалась, показать понятное сообщение и путь к оставшимся файлам.

Для подключения и чтения нужны явные таймауты и понятные сообщения о недоступном сервере, обрыве соединения, повреждённом XML и ошибке записи или проверки SQLite. Отмена пользователем должна отличаться от ошибки загрузки.

До начала применения обновления ошибка или отмена не должны заменять действующую базу. На этапе применения необходимо сохранить предусмотренные механизмы безопасного переключения и восстановления. Утверждать, что прежние данные сохранены, можно только при подтверждённом результате отката или отказе от применения.

## Ограничения реализации

- Сохранить однопроходный SAX-импорт без DOM и без постоянного списка всех игроков в памяти.
- Не менять правила чтения полей, обработки ID, транзакций и проверки целостности ради отображения прогресса.
- Сбор данных и расчёты выполнять в фоне; компоненты Swing обновлять в потоке интерфейса с ограниченной частотой.
- Согласовать отмену с текущим механизмом `SqliteUpdates`, восстановлением прежней базы и закрытием временных хранилищ.
- При повторном использовании `DownloadStats` учесть неизвестный размер XML: действующая модель загрузки программы рассчитана на известный положительный размер.
- Сохранить Java 8+ x32/x64 и работу переносимого профиля рядом с программой.

Задача уточняет оставшуюся часть [BL-06 — управляемые сетевые операции](<../BL-06. Управляемые сетевые операции.md>) для обновления БД игроков. Общие правила расчёта и оформления желательно использовать совместно с загрузчиком обновления программы, сохранив различия двух процессов.

## Критерии приёмки

- [x] При медленной загрузке известного размера видны процент, полученный / общий объём, обе скорости, прошедшее время и оценка окончания чтения XML.
- [x] Показатели обновляются раз в секунду; текущая скорость рассчитана за последние 2 секунды.
- [x] При неизвестном размере нет выдуманного процента, общего объёма или оставшегося времени; загрузка и импорт завершаются корректно.
- [x] При остановке поступления данных текущая скорость снижается до нуля, а недостоверная оценка времени заменяется на «—».
- [x] После получения XML окно продолжает показывать создание индексов, проверку и применение результата; успех не объявляется раньше завершения всей операции.
- [x] Счётчик записей увеличивается во время чтения; итоговое количество игроков соответствует применённой базе.
- [x] Кнопка отмены, Esc и крестик работают на доступных этапах. Отмена до применения сохраняет все записи прежней базы и настройки.
- [x] Обрыв связи, неверный XML и ошибка SQLite сохраняют действующую базу либо корректно восстанавливают её в предусмотренном сценарии применения.
- [x] Потоки и временные подключения закрываются; файлы текущей операции очищаются. Рабочие данные и ранее существовавшие копии не удаляются.
- [x] Повторная попытка после отмены или ошибки проходит без перезапуска программы.
- [x] Отображение прогресса не возвращает полный DOM, дополнительный проход по XML или загрузку всех игроков в память.

Проверять на отдельных синтетических профилях: известный и неизвестный размер, медленная передача, зависшее чтение, разрыв соединения, ошибка в конце XML, повторяющиеся ID, отмена на разных этапах и ошибка применения. До и после отказа или отмены сравнивать логическое содержимое прежней БД и сохранность настроек. Рабочие данные пользователя не использовать.
