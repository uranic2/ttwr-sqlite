## Методика

В новых отдельных папках распакованы оригинальные ZIP старых версий с проверкой их опубликованных SHA-256. В каждой копии подготовлены синтетическая БД, нестандартные настройки и контрольные файлы. Для 0.1.4 дополнительно воспроизведён оставшийся от старой установки документ.

Запускался настоящий EXE старой версии. Тестовый Java-agent нажимал штатные кнопки и наблюдал за состоянием окна, не преобразуя классы программы. Через меню «Справка» запрашивался настоящий GitHub Releases; программа сама скачивала 0.1.5, проверяла её, закрывалась, устанавливала обновление и запускала новый EXE. Сеть и ответы GitHub не подменялись.

В установке использовался исходный помощник соответствующей старой версии. Очистку выполняла уже новая программа при первом запуске — поэтому исправление действует и при переходе со старым установщиком.

## Проверенные результаты

- Исходный `docs/source-provenance.md` отсутствует после запуска 0.1.5. Его точная копия находится в `data/updates/retired-files/<SHA-256>.md`; контрольная сумма копии совпала с исходной во всех шести установках.
- Сохранены **301 игрок** в текущем списке и **1 запись** в области истории рейтинга. Сверены все строки и столбцы таблиц `players` и `metadata`, включая Unicode, рейтинги, признак отрицательного нуля, места, статистику и служебные поля.
- Контрольная сумма логического содержимого БД до и после во всех случаях: `375643510deb1ac9efa37b7e2178622a768036f70127e9b0c577fc728d9393e2`.
- **Весь сохранённый `ttwr.cfg` совпал побайтно** между закрытием старой версии, запуском 0.1.5 и её последующим штатным закрытием. Дополнительно 16 выбранных настроек проверены в работающих окнах обеих версий.
- Папка `runtime` в полном комплекте не изменилась по контрольной сумме всех файлов. В варианте с системной Java она не появилась; Java x32 сохранилась.
- Контрольные файлы в `data/Tours` и `data/Backup` не изменились.
- Все 25 файлов из манифеста установленного комплекта совпали с контрольными суммами. Создана резервная копия исходных EXE и Java-архива старой программы.
- Целостность SQLite — `ok`. После штатного выхода отсутствуют WAL/SHM; старый и новый процессы Java завершились с кодом 0.

Отдельные модульные проверки подтвердили, что очистка затрагивает только известный документ, повторный запуск не создаёт дубликаты, ошибка проверки копии сохраняет исходник, а база, настройки, WAL/SHM, другие документы и Java не изменяются. GUI-проверки подтвердили вызов очистки при обычном старте.

## Выпуск и повторение

[GitHub Actions](https://github.com/uranic2/ttwr-sqlite/actions/runs/43594342573) успешно выполнил сборку и проверки на Java x64/x32 и опубликовал релиз 0.1.5 (на момент проверки; после удаления тегов публичный релиз недоступен) с обоими ZIP. Опубликованные ZIP отдельно скачаны и повторно сверены по SHA-256 и внутреннему манифесту.

```powershell
python scripts/test-live-upgrade.py --jdk 'C:\Tools\jdk-25' --java32 'C:\Tools\jre8-x32' --from-version 0.1.2 --target-version 0.1.5 --require-cleanup --cyrillic
python scripts/test-live-upgrade.py --jdk 'C:\Tools\jdk-25' --java32 'C:\Tools\jre8-x32' --from-version 0.1.4 --target-version 0.1.5 --require-cleanup --cyrillic
```

Нужны сохранённые оригинальные ZIP старых версий в `releases`. Реальный тест ожидает актуальный стабильный релиз 0.1.5. Полные локальные журналы и JSON:

- `.local/live-upgrade-012-015-7ae2e948953e41fb9587fb27677e43ce/`;
- `.local/live-upgrade-014-015-e55cb36e8b0c46d296f9eee6f5effa36/`.

Проверка выполнена на текущей Windows x64, на синтетических данных; рабочая база пользователя не использовалась. Англоязычная Windows с не-ASCII путями в этот реальный прогон отдельно не входила. Известное ограничение помощника 0.1.2 при передаче таких путей может потребовать первого ручного перехода с сохранением `data`.
