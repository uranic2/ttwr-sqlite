# Проверка обновления 0.1.8 → 0.1.9 — 14 ноября 2026 года

**Все три обновления через окно программы прошли успешно. База игроков, настройки и последняя резервная копия сохранились.**

| Исходный комплект 0.1.8 | Java | Папка | Результат |
|---|---|---|---|
| Со встроенной Java | Temurin 25 x64 | Без кириллицы | Успешно |
| Без встроенной Java | Temurin 8u472 x32 | Без кириллицы | Успешно |
| Со встроенной Java | Temurin 25 x64 | Кириллица и пробелы | Успешно |

## Методика

Каждый случай выполнялся в новой отдельной папке. Использованы оригинальные ZIP 0.1.8 с проверенными SHA-256. Подготовлены 301 синтетический игрок, одна историческая запись рейтинга, метаданные, 16 нестандартных настроек и контрольные файлы в `Tours` и `Backup`.

Для проверки хранения обновлений дополнительно подготовлены две старые успешные установки: их образы и копии файлов взяты из сохранённых оригинальных ZIP, одна резервная копия содержит полный манифест с `runtime` без самой Java внутри `backup`. Также добавлены неудачная, незавершённая и неизвестная папки и архив устаревших документов, которые требуется сохранить. Это тестовые остатки установок, а не дополнительные сетевые обновления.

Запускался настоящий EXE 0.1.8. Тестовый Java-agent нажимал штатные кнопки Swing и наблюдал за окном без преобразования классов программы. Программа получала сведения о стабильном релизе с настоящего GitHub, скачивала опубликованный комплект 0.1.9, проверяла его, штатно закрывалась, устанавливала обновление и запускала 0.1.9. Ответы GitHub и загрузка не подменялись; авторизация в программу не добавлялась.

После старта 0.1.9 наблюдатель дожидался автоматической проверки последней копии и конечного состояния старых папок, затем штатно закрывал программу. Он не вызывал очистку вместо программы и не удалял старые установки сам. Версия 0.1.8 уже поддерживает очистку, поэтому часть её собственной истории могла очищаться ещё до выхода; проверяется итоговое состояние перехода.

## Результаты

- Сохранены все строки и столбцы таблиц `players` и `metadata`: 301 текущий игрок и одна историческая запись, включая Unicode, рейтинги, статистику и служебные значения.
- Логический SHA-256 БД до и после во всех случаях: `375643510deb1ac9efa37b7e2178622a768036f70127e9b0c577fc728d9393e2`. `PRAGMA integrity_check` вернул `ok`.
- Сохранённый при штатном закрытии 0.1.8 файл `ttwr.cfg` совпал побайтно с файлом при старте 0.1.9 и после её закрытия. Все 16 выбранных настроек дополнительно проверены в работающих окнах.
- Последняя папка обновления осталась; маркер `confirmed-start.txt` подтверждает 0.1.9. В её `backup` все 25 резервируемых файлов программы 0.1.8 сверены с оригинальным ZIP. Исходный манифест сохранён побайтно, включая полный манифест со ссылками на встроенную Java.
- Встроенная `runtime` не изменилась по хешу всех файлов. В варианте с системной Java она не появилась; сохранилась Java x32.
- Обе подготовленные старые успешные установки отсутствуют после обновления. Неудачная, незавершённая и неизвестная папки, а также архив устаревшего документа сохранены.
- Контрольные файлы в `Tours` и `Backup` не изменились. Все 25 файлов установленного комплекта 0.1.9 совпали с его манифестом; версия подтверждена в архиве и статусной строке окна.
- Оба процесса Java в каждом переходе завершились с кодом 0. После штатного выхода WAL/SHM отсутствуют.

Геометрия начального искусственного профиля могла адаптироваться к экрану при первом запуске 0.1.8. Побайтное сравнение обновления выполнялось после штатного сохранения исходной программой.

## Границы проверки

Это проверка реальной установки и сохранности данных на текущей Windows x64 и синтетических профилях. Рабочие данные пользователя не использовались.

В переходе использовался загрузчик исходной 0.1.8. Новое окно прогресса и отмены из 0.1.9 начинает использоваться уже установленной новой программой; его отдельные сценарии с имитацией HTTPS описаны в [отчёте о загрузке](Прогресс-загрузки-и-отмена.md).
