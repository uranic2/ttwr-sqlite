## Методика

В новых отдельных папках распакованы оригинальные ZIP 0.1.6, SHA-256 сверены со значениями опубликованного выпуска. Подготовлены 301 синтетический игрок, одна историческая запись рейтинга, метаданные, 16 нестандартных настроек и контрольные файлы турниров/резервных копий.

Дополнительно в каждом профиле воспроизведены две старые успешные установки: образы и резервные копии взяты из сохранённых оригинальных ZIP 0.1.5 и 0.1.6 без Java и проверены по манифестам. Это тестовая история установок, а не результат двух дополнительных обновлений через сеть. Также добавлены файлы неудачной и незавершённой установок, посторонние заметки и архив устаревших документов, которые должны сохраниться.

Запускался настоящий EXE 0.1.6. Java-agent нажимал штатные кнопки Swing без изменения классов программы. Через меню «Справка» программа обращалась к настоящему GitHub, скачивала опубликованный комплект 0.1.7, проверяла его, штатно закрывалась, устанавливала обновление и запускала новый EXE. Ответы GitHub и загрузка не подменялись.

После старта 0.1.7 наблюдатель ждал автоматическую очистку и подтверждение резервной копии. На ожидание отводилось 45 секунд; при отсутствии очистки окно затем штатно закрывалось. Сам тест не вызывал `UpdateStorage` и не удалял старые папки вместо программы.

## Сохранность данных

Во всех трёх переходах подтверждено:

- Полное совпадение всех строк и столбцов `players` и `metadata`: 301 текущий игрок и одна историческая запись.
- Логический SHA-256 БД: `375643510deb1ac9efa37b7e2178622a768036f70127e9b0c577fc728d9393e2`, одинаковый до и после; целостность `ok`.
- Сохранённый при штатном закрытии 0.1.6 `ttwr.cfg` совпал побайтно с файлом при старте 0.1.7 и после её закрытия. Все 16 выбранных настроек также проверены в работающих окнах.
- Встроенная Java и контрольные файлы в `Tours` и `Backup` не изменились. В комплекте без Java `runtime` не появилась.
- Все 25 файлов установленного комплекта 0.1.7 совпали с манифестом.
- Последняя папка обновления и её `backup` остались. Все 25 файлов программы из комплекта 0.1.6, подлежащих резервированию, проверены по исходному ZIP.
- Неудачная, незавершённая и неизвестная папки, а также архив устаревшего документа сохранены.
- Старый и новый процессы Java завершились с кодом 0. После выхода WAL/SHM отсутствуют.

Начальная искусственная геометрия окна могла адаптироваться к экрану при первом запуске 0.1.6. Побайтное сравнение обновления выполнялось после штатного сохранения старой версией.

## Причина ошибки очистки полного комплекта

При обновлении полного комплекта устанавливается ZIP `system-java`, а существующая `runtime` сохраняется на месте. Установщик резервирует заменяемые файлы программы и исходный `checksums.json` полного комплекта.

В исходном манифесте 0.1.6 со встроенной Java **345 записей**, включая **320 файлов `runtime`**. В `backup` находятся 25 резервируемых файлов программы и исходный манифест; копии Java там нет. Сама рабочая Java остаётся на месте и не повреждается.

`UpdateStorage.candidate()` вызывает `UpdateInstaller.verify()` для резервной копии и ожидает все файлы исходного манифеста. Проверка не находит 320 файлов Java, поэтому папка нового обновления не признаётся пригодной. Маркер `confirmed-start.txt` не создаётся и очистка более старых папок не начинается.

У исходного комплекта без Java манифест содержит 25 записей; все они присутствуют в резервной копии. В этом случае подтверждение и очистка проходят.

Нужно согласовать проверку резервной копии с её фактическим составом: отделить резервируемые файлы приложения от сохраняемой на месте `runtime`, сохранив проверку всех файлов приложения по SHA-256. Ослаблять проверку произвольных отсутствующих файлов нельзя. Для исправления понадобится новый выпуск; опубликованные ZIP 0.1.7 в ходе этой проверки не менялись.

Полные журналы, снимки состояния, профили и диагностика: `.local/live-upgrade-016-017-0b9135b9ca7b4d54872e0693c83f2087/`, файлы `summary.json` и `diagnostics.json`.

Проверка выполнена на Windows x64 и синтетических данных. Рабочая установка пользователя не использовалась. Код программы, тег и публичный релиз не изменялись; изменены только сценарий проверки, тестовый агент и документация.
