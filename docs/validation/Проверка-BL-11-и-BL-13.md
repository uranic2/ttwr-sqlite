# BL-11 / BL-13 — загрузка игроков и импорт профиля TTWR

Дата проверки: **15 ноября 2026 года**. Реализация подготовлена к выпуску **0.1.10**. Описанные ниже проверки разработки выполнялись до повышения VERSION, на встроенной версии 0.1.9. После повышения номера Java-архив пересобирается; проверки выпуска и обоих комплектов повторяет GitHub Actions.

## Согласованное поведение

Штатное сетевое обновление использует новое DBUpdateDlg; DBLoadDlg остаётся для открытия локальных баз. Импорт оригинального TTWR и загрузка с сервера используют PlayersUpdateSession, общий прогресс, отмену и замену комплекта.

Показатели обновляются каждые 1000 мс. Общий DownloadStats поддерживает неизвестный размер и рассчитывает текущую скорость за последние 2 секунды по монотонным часам. Процент и ETA доступны только при известной длине XML; после чтения скорость и ETA не выдаются за текущие показатели индексации/проверки. SAX разбирает Players.xml один раз без полного DOM; текущий счётчик отличает прочитанные записи от уникальных игроков. Успех показывается после применения и загрузки страницы таблицы.

При первом запуске исходный профиль предлагается только после обнаружения и согласия. Отсутствие игроков само по себе не считается первым запуском. Из меню можно выбрать другую папку DB. Все четыре входных файла обязательны; ссылки берутся из db.xml и проверяются на выход за пределы папки, абсолютные/сетевые пути и junction. Источник только читается и сверяется перед применением. В локальном комплекте сохраняются имя/дата, игроки, проверенные шаблоны и регионы; настройки и турниры оригинального TTWR не импортируются.

Кнопка отмены, Esc и крестик имеют общий обработчик. Отключение сети и работа SQLite выполняются вне Swing; длительный SQL прерывается через ProgressHandler. До применения отмена оставляет прежнюю базу активной. На этапе замены/отката отмена защищена от повторного запроса.

DbPackageTransaction резервирует каталог DB, копируя SQLite через backup API с учётом WAL и всех scope. Копии остаются в data/Backup/DB-before-import-*. Журнал data/db-package.pending защищает замену четырёх файлов и хранит имя своего временного файла записи. После прерывания процесса восстановление выполняется до открытия базы. Повреждённая копия блокирует подготовку профиля, сохраняет журнал и отключает повторную операцию в окне. Постоянные WAL/SHM вручную не удаляются.

## Ограничения

- HTTPS в автоматических проверках имитируется. Реальное скачивание списка игроков и реальное обновление приложения через публичный сервер в рамках этих задач не выполнялись.
- Для первого запуска тест передаёт синтетическую исходную папку; личный профиль в AppData не читается.
- Проверка аварии использует реальное завершение дочерней JVM в контролируемом состоянии частичной замены. Остаток частично скопированного временного файла дополнительно моделируется отдельно. Это не проверка внезапного отключения питания.
- Нехватка места на настоящем заполненном диске не создавалась. Ошибка применения проверена блокировкой файла, ошибка восстановления — повреждением копии.
- Java x32 проверена на Windows x64; отдельная 32-разрядная Windows не проверялась.
- После аварийного завершения может остаться подготовленная папка data/.players-operation-* для диагностики. Неизвестные операции и ранее созданные резервные копии автоматически не удаляются.
- Старые фоновые проверки наличия обновлений остаются за рамками BL-11; BL-06 сохраняет частичный статус.
- Ускорение и снижение памяти не измерялись; новые численные обещания производительности не делаются.
