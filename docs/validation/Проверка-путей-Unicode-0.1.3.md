# Проверка передачи путей установщику — 14 ноября 2026 года

Первая проверка GitHub Actions для 0.1.2 выявила `InvalidPathException`: при запуске дочерней Java кириллица в аргументе пути заменялась на `?` в англоязычной Windows. Сборка, проверки SQLite и интерфейса до этого этапа проходили. Ошибка подтверждена локально путём с японскими символами, отсутствующими в системной кодировке.

В 0.1.3 пути установки и временных файлов передаются в Base64 от UTF-8. Установщик запускается из своей рабочей папки с относительным classpath `updater.dat`; кириллица не используется в аргументах командной строки. Тест использует тот же `helperProcess()`, что и приложение, а не отдельную имитацию запуска.

Локально полный набор проверок выполнен на Java 25 x64 и Java 8u472 x32, включая штатное закрытие SQLite, отмену выхода, установку после освобождения блокировки, резервирование, откат и native-перезапуск. Для установщика используется папка с пробелами, кириллицей и японскими символами; `data` и `runtime` сохранены.

Для CI добавлены журнал дочернего процесса и диагностические артефакты при ошибке. Проверка релиза в workflow дополнительно распаковывает оба ZIP, сверяет контрольные суммы и встроенную версию, запускает EXE на Java x32 и комплектной Java x64 и проверяет пустую БД.
