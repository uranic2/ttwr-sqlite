# Запуск без интернета — 15 ноября 2026 года

## Результат

**TTWR SQLite 0.1.10 запускается при недоступности HTTP/HTTPS.** В шести итоговых сценариях главное окно стало доступно, фоновые проверки не блокировали интерфейс, локальная база читалась, программа штатно завершилась. Изменение кода приложения не потребовалось.

Проверена сборка текущего коммита `865b2282296cf6592322c079b09738e9509231d8`. Перед прогоном исходники src/main, tools и config сравнены с копией, из которой собран комплект; различий нет. Все файлы исходного комплекта сверены с checksums.json.

## Методика

Запускался настоящий `ttwr-sqlite.exe` из шести отдельных копий комплекта system-java. Java выбиралась запускателем через JAVA_HOME; выбранные версия и разрядность подтверждены журналами. AppData для теста указывал на отдельную пустую папку; реальные профили не использовались.

Потеря сети моделировалась тестовым Java-агентом: обращения HTTP/HTTPS перехватывались до соединения и завершались UnknownHostException. В сценариях тайм-аута агент ждал настроенный connect timeout 15 секунд и затем возвращал SocketTimeoutException. Два последовательных запроса даты базы и заголовка занимали около 30 секунд; проверка программы шла параллельно в фоне. Ответы настоящих серверов не подменялись успешными данными, соединения с ними не устанавливались.

Агент пропускал предварительный запуск Java для определения версии и подключался только к процессу приложения. Наблюдение выполнялось через Swing Timer, с общим ограничением времени и завершением тестового процесса при сбое. Штатное кратковременное окно DBLoadDlg при чтении локальной базы не считалось сетевой ошибкой.

## Что фактически проверено

- В каждом сценарии произошли два неуспешных обращения проверки базы и одно обращение проверки GitHub Releases; проверка не была пропущена из-за суточного кеша.
- После отказа фоновых запросов не появились блокирующие сообщения сетевой ошибки или окна обновления. Маркер program-update-check.txt не создавался: неуспешная проверка не отмечалась успешной.
- Главное окно оставалось включённым; таймер интерфейса продолжал работать и во время ожидания сетевых тайм-аутов. В итоговых прогонах наибольший наблюдавшийся интервал между его событиями составил 505 мс, порог проверки — 2 секунды. Это наблюдение в тестовой среде, а не обещание производительности на любом компьютере.
- Индикатор базы сообщал о невозможности проверить наличие обновлений, не утверждая актуальность или устаревание базы.
- Из главного окна открывались локальные сведения «Информация о БД игроков»; количество игроков читалось правильно, диалог закрывался своей кнопкой.
- Для существующего профиля сравнен SHA-256 представления всех столбцов всех строк players, упорядоченных по scope и id: до и после запуска значения совпали. Для первого запуска база осталась пустой. PRAGMA integrity_check вернул ok.
- Оба процесса — Java и native-запускатель — завершились штатно с кодом 0. После закрытия и контрольного чтения базы не осталось Players.sqlite-wal и Players.sqlite-shm.

## Свидетельства

Тестовые копии, исходники агента, журналы и снимки: `.local/offline-start-1794764743683`. Для пяти сценариев использованы итоговые папки с окончанием run3; для первого запуска Java 8 — run4, после уточнения обработки штатного окна чтения базы. Предварительные отладочные попытки в шесть успешных результатов не включены.

В каждой успешной папке есть data/launcher.log, data/launcher-java.log, а в temp/offline-evidence — result.txt, main.png и database-info.png. Снимок главного окна с синтетическими игроками после сетевых тайм-аутов просмотрен. Рабочие базы, настройки и подключения пользователя не менялись.

## Ограничения

Это проверка недоступности HTTP/HTTPS внутри JVM с настоящим запускателем и интерфейсом. Сетевой адаптер Windows физически не отключался. DNS, VPN, системные прокси, captive portal, сетевые диски и работа Windows при отключении адаптера отдельно не проверялись.

Java x32 недоступна и в этот прогон не включена. Проверены системные Java 8/25 x64; полный комплект со встроенной runtime отдельно не запускался. Ручная загрузка игроков, ручная установка обновления и отправка турнира в рамках проверки старта не выполнялись.

Наличие офлайн-запуска не делает сетевые функции доступными без интернета. Для работы с игроками без сети нужна уже заполненная локальная база; первый запуск создаёт пустую.
