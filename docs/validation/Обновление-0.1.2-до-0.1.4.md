**Обновление прошло успешно во всех трёх проверенных сценариях. Список игроков, история рейтинга, настройки и Java сохранились.**

|---|---|---|---|
| Со встроенной Java | Temurin 25.0.5 x64 | Без кириллицы | Установка и автоматический запуск 0.1.4 прошли |

| Со встроенной Java | Temurin 25.0.5 x64 | С кириллицей и пробелами | Установка и автоматический запуск 0.1.4 прошли |

## Как проверяли

Использованы сохранённые оригинальные ZIP версии 0.1.2. Их SHA-256 сверены с опубликованными ранее контрольными суммами. Каждая проверка выполнялась в новой отдельной папке; рабочие данные пользователя не использовались.

Запускался настоящий `ttwr-sqlite.exe` из распакованного комплекта 0.1.2. Тестовый Java-agent нажимал штатные кнопки и записывал наблюдения, без преобразования классов программы. Через меню «Справка» запускалась реальная проверка GitHub Releases, подтверждались загрузка 0.1.4 и закрытие для установки. Сеть и ответ GitHub не подменялись.

Установку выполнял исходный помощник из 0.1.2. Он создал резервную копию файлов, установил загруженный комплект и сам запустил новый EXE. После появления настоящего окна 0.1.4 проверялись версия в статусной строке, данные и настройки. Затем окно закрывалось штатно; оба процесса Java завершались с кодом 0.

## Что сохранилось

- **301 игрок** в текущем списке и **1 запись** в отдельной области истории рейтинга.
- Все столбцы обеих таблиц SQLite (`players`, `metadata`), включая профили, Unicode-имена, рейтинги, флаги, места и обе группы статистики. Сравнивались все строки в установленном порядке; контрольная сумма логического содержимого базы до и после совпала во всех трёх случаях.
- Контрольный игрок с именем «Ёлкин José — контроль обновления», рейтингом с признаком отрицательного нуля, дельтой `12.75` и заданной статистикой сохранился.
- **16 заданных настроек** проверены внутри работающих окон обеих версий: шрифт, режимы отображения, параметры работы со списком турниров и игроками, отключение автоматического обновления базы, параметры памяти и тестовые поля отправителя почты.
- **Весь `ttwr.cfg` побайтно совпал** между штатным закрытием 0.1.2 и запуском 0.1.4. После штатного закрытия 0.1.4 он также совпал с файлом, сохранённым 0.1.2.
- Папка `runtime` в полном комплекте сохранилась по контрольной сумме всех файлов. В варианте с системной Java папка `runtime` не появилась, сохранилась Java x32.
- Контрольные файлы в `data/Tours` и `data/Backup` остались без изменений.

Для каждой установленной копии проверены все **25 файлов** из манифеста скачанного комплекта. `PRAGMA integrity_check` вернул `ok`, WAL/SHM после закрытия отсутствовали, исходные EXE и Java-архив сохранились в резервной копии установщика. Наблюдатель читал закрытую БД в режиме `immutable`, чтобы сама проверка не создавала WAL/SHM.

## Уточнения и границы

При первом штатном выходе из 0.1.2 программа записала фактические положение и размер окна. Поэтому файл из искусственно подготовленного профиля отличается от сохранённого после первого запуска. Эти изменения произошли до установки; обновление сохранило полученный файл целиком.

Обновление заменяет перечисленные файлы, но не удаляет устаревшие: в обновлённых копиях остался старый отдельный документ из комплекта 0.1.2. В новом ZIP 0.1.4 его нет; на сохранность базы и настроек это не влияет.

Проверка выполнена на текущей Windows x64. Англоязычная Windows с не-ASCII путём установки здесь отдельно не проверялась. У исходного установщика 0.1.2 есть ранее выявленное ограничение передачи таких путей; если оно проявится, первый переход выполняется вручную с сохранением `data`. Исправление передачи путей находится в версиях начиная с 0.1.3.

Это проверка сохранности синтетических данных и работы настоящего обновления, а не испытание каждого турнирного сценария или производительности полного списка игроков.

## Повторение

Нужны локальные оригинальные ZIP 0.1.2 в `releases`, Windows, JDK 17+ и Java 8 x32:

```powershell
python scripts/test-live-upgrade.py --jdk 'C:\Tools\jdk-25' --java32 'C:\Tools\jre8-x32' --target-version 0.1.4 --cyrillic
```

Тест ожидает, что актуальный стабильный релиз GitHub — 0.1.4. Он не включён в обычный CI: использует настоящий сервер и сохранённые старые комплекты. Журналы, снимки окон и JSON последней успешной проверки сохранены локально в `.local/live-upgrade-012-014-c6976f27691542d6a4b6a3f009f33484/`.
