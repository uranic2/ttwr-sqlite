# Главное меню и информация о БД игроков

Дата: 15.11.2026. База версии: VERSION 0.1.10; изменения не опубликованы.

## Изменения

- Верхнее меню «Настройка»: два прежних действия «Общие настройки» и «Настройка страницы печати», с сохранением обработчиков и горячих клавиш.
- «База данных» → «БД игроков», «Обновить базу данных» → «Обновить БД игроков из интернет»; ручной пункт резервной копии удалён из меню. Автоматическое резервирование не менялось.
- Модальное окно информации читает путь действующего SQLite, размер файла в Кбайтах (1024 байта, два десятичных знака, разделители разрядов), SQL count для scope=current и локальное время успешной интернет-загрузки. Чтение выполняется вне EDT, без сети и принудительного checkpoint. Значения можно копировать. Используется общее оформление DialogStyle.
- В существующей таблице metadata сохраняется last_internet_update в миллисекундах Unix. Отметка попадает в подготовленный комплект и устанавливается вместе с ним; отмена, ошибка и откат сохраняют предыдущую отметку. Локальный импорт сбрасывает её в 0. Отсутствие/некорректное значение отображается как «Нет сведений». Дата публикации DBMain.date остаётся отдельным свойством. Изменения схемы не требуются.

## Среда и методика

Windows x64, JDK 25.0.1 x64, Java 8u321 x64, рабочие классы/тесты --release 8, инструменты --release 17. Сборка выполнена в .local/menu-info-1794755365261: основной build/image содержит пользовательскую data и не изменялся. Взяты текущие исходники со всеми существовавшими до задачи изменениями. Исходный архив сверен с lock-файлом, VerifySqliteArchive прошёл, стартовый каталог содержит 0 игроков. C-код не менялся, использован существующий запускатель, сборка с -SkipNative.

В этой среде прямые native-вызовы из PowerShell не запускались. Только в изолированной копии native-команды build.ps1/test.ps1 направлены через Start-Process с ожиданием и проверкой кода; аргументы, компилятор и тестовые классы сохранены. В основном репозитории такого адаптера нет.

## Результаты

- Основная последовательность test.ps1 прошла на обеих Java: SQLite, WeakCacheRollbackChecks, shutdown/WAL/SHM, переносимый профиль, RemoteFlowChecks, SinglePassImportChecks, перенос профиля и восстановление пакета, DatabaseDateChecks, поток игроков, показатели загрузки, программное обновление, DownloadChecks и хранение копий.
- DatabaseDateChecks дополнен проверкой сохранения времени интернет-загрузки после повторного открытия, сохранности прежней отметки при отмене/ошибке/откате и отсутствия сетевой отметки после локального импорта.
- MainMenuUiChecks проверяет настоящее преобразованное главное окно: подписи, два исходных объекта действий настройки с обработчиками, отсутствие ручного резервирования, путь/размер/число игроков/время в новом окне, формат 1 234,50 Кбайт, неизвестную дату и кнопку закрытия. Снимок просмотрен.
- Первый GUI-прогон обнаружил гонку теста: меню открывалось из вложенного цикла событий стартового DBLoadDlg. Тест теперь ждёт завершения стартовых диалогов. Повторная проверка прошла на Java 25 и Java 8.
- Остальные GUI-проверки: DatabaseStatusUiChecks update/restart; повреждённая копия; PlayerUpdateUiChecks button/escape/close/success/unknown/error/import; первый импорт accept/decline; ProgramUpdateUiChecks current/cancel/storage; DownloadUiChecks button/escape/close/success/error. Выполнены на обеих Java.
- git diff --check и проверка публичного дерева прошли.

Подробные журналы, тестовые профили и снимки находятся в .local/menu-info-1794755365261. Копия программы для ручного просмотра подготовлена в dist/ttwr-sqlite-menu-preview-1794755670218, без пользовательской data и без встроенной Java.

## Ограничения

Java x32 недоступна; DPI 125–200%, реальные серверы игроков/GitHub и установка с перезапуском не проверялись. HTTPS в тестах синтетический; новая проверка меню отключает сеть. Размер относится к основному SQLite-файлу, без WAL/SHM. Старые базы не имеют достоверного времени интернет-загрузки до следующего успешного обновления. Коммит, push, упаковка релиза и публикация не выполнялись.
