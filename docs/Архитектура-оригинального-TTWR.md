# Архитектура оригинального TTWR

TTWR — настольная программа для проведения турниров по настольному теннису: она хранит сведения об игроках, помогает составлять группы и сетки, вводить результаты встреч и рассчитывать изменения рейтинга.

Здесь описан **оригинальный TTWR 1.4.2.1** из `vendor/upstream/ttwr.dat`, а не его SQLite-модификация.

## Язык и интерфейс

Основная программа написана на **Java**, интерфейс — на **Swing**. Окна, кнопки, меню и таблицы работают по событиям: действие пользователя вызывает обработчик, который меняет данные и обновляет отображение. При запуске выбирается оформление Nimbus, если оно доступно.

В Windows `ttwr.exe` служит запускателем Java-программы. Сама программа находится в `ttwr.dat`: несмотря на расширение, это JAR-архив со скомпилированными классами `.class`, значками PNG и служебным манифестом. Исходных файлов Java и файлов визуального дизайнера форм в архиве нет.

## Форматы и структуры хранения

Оригинал использует профиль **`%APPDATA%\TTWR`**. Пути к базе, турнирам и резервным копиям задаются в настройках и могут отличаться от стандартных.

| Файл или папка | Содержимое |
|---|---|
| `ttwr.cfg` | Настройки в XML: пути, положение окна, параметры интерфейса, сети и обновления |
| `DB/db.xml` | Заголовок базы: имя, дата обновления и имена файлов игроков, регионов и шаблонов |
| `DB/Players.xml` | Полный каталог игроков: профиль, рейтинг, места и статистика |
| `DB/Regions.xml` | Справочник регионов |
| `DB/Templs.xml` | Шаблоны проведения турниров |
| `Tours` | Файлы турниров в XML; автосохранения имеют окончание `.autosave.xml` |
| `RLists` | Предусмотренный каталог XML рейтинговых списков; автоматическое заполнение в исследованном архиве не реализовано |
| `Backup` | Каталог резервных копий, путь к которому хранится в настройках |

Здесь «база данных» — **набор XML-файлов**, а не локальный SQL-сервер. SQLite в оригинале нет.

При открытии каталога программа целиком читает `Players.xml` и строит DOM — дерево XML в памяти. Затем создаёт объекты `Player` и помещает их в `HashMap`: по ID можно быстро получить нужного игрока. Списки стран, регионов и городов также находятся в памяти. Поиск, фильтрация и сортировка работают с загруженными объектами.

У игрока есть профиль: ID, имя, страна, регион, город, дата рождения и пол. Отдельно хранятся рейтинг, место, изменение рейтинга и статистика. Участник турнира — отдельный объект, связывающий игрока с конкретным соревнованием; предусмотрены также пары и команды. Турнир содержит участников, этапы и встречи.

При сохранении каталога снова формируется XML всего списка. Даже небольшая правка может требовать перезаписи большого файла. Полная загрузка XML и создание объектов объясняют рост времени запуска и потребления памяти на большой базе.

## Обновление списка игроков

1. `Updater` запрашивает дату базы у сервиса `db_last_updated.php`. Если получить её не удалось, пробует прочитать дату из серверного `db.xml`.
2. Серверная дата сравнивается с DBMain.date, прочитанной из DB/@date локального DB/db.xml (формат d.M.yyyy-H:m:s). Сравнивается и время, а не только календарный день. Если серверная дата строго новее либо локальная дата неизвестна, база считается устаревшей. Интерфейс показывает наличие обновления; настройка позволяет предложить обновление при запуске.
3. Главное окно проверяет наличие неучтённых турниров и предлагает сохранить изменённую базу. Для загрузки создаётся отдельный объект `DBMain`, прежний временно сохраняется.
4. Диалог `DBUpdateDlg` запускает загрузку в отдельном потоке. По серверному `db.xml` программа читает указанные в нём файлы игроков, регионов и шаблонов.
5. Полный XML игроков разбирается через DOM и превращается в новый каталог объектов. Во время обновления также записывается промежуточный `Players.xml.tmp`.
6. После успешной загрузки DBUpdateDlg$9 повторно вызывает Updater.GetDBLastUpdatedData и, если дата получена, присваивает её новому DBMain.date вместо даты из заголовка. Затем программа сохраняет новую базу по прежнему локальному пути; DBMain.SaveXML записывает DB/@date. TTRClient.UpdateDB запускает повторную проверку свежести и обновляет представления. Если загрузка или сохранение не удались, главное окно возвращает ссылку на прежний объект базы.

Статус jStatusDB показывает локальную дату в формате dd.MM.yyyy. Обработчик TTRClient$24.OnCompleteDBCheck выбирает question.png при ошибке проверки, warning.png при наличии более новой серверной даты и ok.png при актуальном каталоге. [Подробная проверка даты](validation/Дата-базы-и-статусная-панель.md).

Это загрузка полного каталога, а не получение только изменившихся игроков. Возврат прежнего объекта в памяти не означает транзакционный откат всех файлов на диске.

## Обновление программы

Обновление самой программы выполняется отдельно от обновления игроков:

1. При открытии главного окна `Updater` в фоновом потоке читает с сервера файл `version`.
2. Номер сравнивается с текущим по четырём числовым частям. При наличии новой версии дополнительно проверяется доступность `ttwr_setup.exe`.
3. Пользователь нажимает на индикатор версии и выбирает, куда сохранить установщик. Программа скачивает его и показывает процент загрузки.
4. После скачивания предлагается закрыть TTWR и установить обновление. При согласии запускается `ttwr_setup.exe` и отправляется событие закрытия главному окну.

Заменой файлов занимается **внешний установщик**. В проверенном Java-коде этого механизма нет проверки SHA-256, манифеста комплекта и собственного отката установки, которые появились в SQLite-модификации.

## Устройство программы и основные классы

Это единое настольное приложение. Практически его можно разделить на интерфейс, модель игроков и турниров, чтение и запись файлов и сетевые операции. Границы не строгие: главное окно координирует многие действия, а классы данных сами умеют читать и записывать XML.

| Класс или группа | Роль простыми словами |
|---|---|
| `TTRClient` | Главное окно и координатор: открытие и сохранение базы, работа с турнирами, запуск обновлений и завершение программы |
| `DBMain` | Объединяет каталог игроков, шаблоны и сведения о турнирах; хранит имя, путь и дату базы |
| `DBPlayers`, `Player` | Каталог игроков и отдельный игрок с профилем, рейтингом и статистикой |
| `DBTours`, `RatingList` | Модели турниров и рейтинговых списков; часть операций загрузки, сохранения и ведения истории является заглушками |
| `Tournament`, `THeader` | Турнир: описание, участники, этапы, встречи и занятость столов; расчёт рейтинговых изменений |
| `TStage`, `GroupTable`, `GroupGrid`, `GroupList` | Этапы и организация участников в таблицы, сетки и списки |
| `Member`, `MemberDouble`, `MemberTeam` | Участник турнира: одиночный игрок, пара или команда |
| `Game`, `GameTeam`, `GameFormat` | Встречи, командные матчи и правила их проведения |
| `DBTempls`, `TTemplate` | Каталог шаблонов и отдельный шаблон турнира |
| `ttr.UI` | Окна и панели: список игроков, редакторы, представление турнира, ввод счёта, второй экран и диалоги обновления |
| `Settings`, `Utility`, `Updater` | Настройки, общие операции с XML/файлами/сетью и проверка обновлений |

Например, при вводе результата окно из `ttr.UI` обращается к объектам встречи и турнира, они обновляют своё состояние, после чего интерфейс перерисовывает таблицу или сетку. Сохранение переводит эти объекты обратно в XML.
