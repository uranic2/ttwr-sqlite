# TTWR SQLite — переносимая версия

## Что нового

- Игроки и рейтинги хранятся в SQLite; поиск, фильтры и сортировка выполняются в БД.
- Список показывает страницы по 100 игроков, подтверждённые изменения сохраняются сразу.
- База, настройки, журналы, турниры и резервные копии находятся в **`data` рядом с `ttwr-sqlite.exe`**.
- Профиль старого TTWR остаётся независимым. С версии 0.1.10 базу из него можно импортировать после подтверждения при первом запуске либо через меню.
- Java 25.0.5 x64 и драйвер SQLite включены в полный комплект. **Если папки `runtime` нет, используется установленная Java 8 или новее — x64 либо x32.**
- Стартовая база пустая: **0 игроков**. Каталог загружается обновлением XML с сервера либо импортом базы оригинального TTWR.

## Запуск на другом компьютере

1. Распакуйте **весь архив** в папку с правом записи, например `C:\Apps\TTWR-SQLite`. Из ZIP программу не запускайте.
2. Запустите **`ttwr-sqlite.exe`**. Он создаст отдельную папку `data` рядом с EXE.
3. Выберите **«БД игроков → Обновить БД игроков из интернет → Обновить»** и дождитесь загрузки игроков. Для этого нужен интернет.

Нужна Windows 10/11 x64. Структура комплекта:

```text
ttwr-sqlite.exe
app/                 — программа, библиотеки и пустая стартовая база
runtime/             — встроенная Java; необязательна при установленной Java 8+
README.md
data/                — создаётся при первом запуске
  ttwr.cfg           — настройки SQLite-версии
  ttwr_data.xml      — дополнительные данные приложения, когда они сохранены
  DB/Players.sqlite  — рабочая база игроков
  DB/db.xml          — заголовок базы
  Tours/             — турниры
  Backup/            — резервные копии
  stats/             — экспорт статистики
```

Переносите всю папку программы вместе с `app` и **`data`**, чтобы сохранить свою базу и настройки. `runtime` можно не переносить, если на другом компьютере есть подходящая Java. При новом запуске основные пути привязываются к текущей папке программы. AppData старого TTWR остаётся отдельно; данные предыдущей SQLite-сборки оттуда не переносятся автоматически.

Для обновления существующей переносимой копии сохраняйте свою папку `data`: не заменяйте её пустой стартовой базой. В распространяемом ZIP папки `data` нет.

## Как выбирается Java

Запускатель сначала проверяет `runtime/bin/java.exe`, затем `JAVA_HOME`, `JRE_HOME`, Java в PATH и реестр Windows в обеих разрядностях. Проверяется, что Java действительно запускается и её версия не ниже 8. Если найденная среда не подходит, поиск продолжается.

Установленная Java может быть **32-разрядной**, даже на Windows x64. Новый EXE запускает её отдельным процессом. Для Java x32 установлен лимит кучи 512 МБ, для x64 — 1024 МБ. При наличии исправной комплектной `runtime` она имеет приоритет.

Есть два ZIP-комплекта: `ttwr-sqlite-<версия>-windows-x64.zip` со встроенной Java и `ttwr-sqlite-<версия>-system-java.zip` без неё. Приложение и пустая стартовая БД одинаковы. Java x32 проверена на Windows x64; отдельная 32-разрядная Windows не проверялась.

## Если не запускается

Не отделяйте EXE от `app`. Если используете комплектную Java, сохраняйте всю папку `runtime`. Её проверка из папки программы:

```bat
runtime\bin\java.exe -version
```

Ожидается Temurin 25.0.5. Без `runtime` можно проверить установленную Java командами `java -version` и `where java`. Если Java не найдена, запускатель показывает сообщение; установите Java 8+ либо верните `runtime`. Для явного выбора установленной среды задайте `JAVA_HOME` на папку JRE/JDK, без суффикса `bin`.

Выбранная Java, разрядность и лимит памяти записываются в `data/launcher.log`; ошибки запуска JVM — в `data/launcher-java.log`. Журналы программы: `data/ttwr-sqlite-startup.log` и `data/ttwr.err`. Если папка недоступна для записи, переместите весь комплект в доступную папку. Перехода на AppData при ошибке нет. При неполной существующей локальной базе файлы автоматически не заменяются.

Подробности: [описание изменений](Изменения.md).

## Обновление программы (с версии 0.1.2)

Пункт **«Справка → Проверить обновления программы…»** проверяет новые стабильные релизы GitHub. При запуске также выполняется фоновая проверка, не чаще раза в сутки. Для установки согласитесь на загрузку, затем на закрытие и перезапуск. Отмена штатного выхода отменяет установку.

Рабочие база, настройки и папка `runtime` сохраняются. Резервные копии заменяемых файлов и журнал установки находятся в `data/updates`. Java автоматически не обновляется. С версии 0.1.1 первый переход выполняется вручную. Подробнее: [обновление программы](Обновление-программы.md).

## Загрузка и импорт списка игроков (с версии 0.1.10)

Новое окно загрузки и импорт профиля доступны начиная с версии 0.1.10.

При первом запуске новой копии программа предлагает импорт, если обнаружен оригинальный профиль в `%APPDATA%\TTWR\DB`. Импорт начинается только после согласия. При отказе или отсутствии источника создаётся обычная пустая база. Повторный запуск, существующая пустая база и неполная `data` не вызывают повторного автоматического предложения.

Для переноса позже используйте **«БД игроков → Импорт профиля TTWR…»** и выберите папку DB. Закройте оригинальный TTWR. Нужны `db.xml` и все три XML, указанные в нём: игроки, шаблоны и регионы. Имена могут отличаться от стандартных. Настройки старого TTWR, турниры, пароли, журналы и архивы не импортируются. Источник используется только для чтения; объединения с текущим каталогом нет.

Сохраните и закройте открытые турниры по предложению программы. После проверки комплекта подтвердите замену. В локальной `data/DB` появятся `Players.sqlite`, `Templs.xml`, `Regions.xml` и согласованный `db.xml`. Имя и дата базы сохраняются, если заданы в исходном заголовке. Настройки и файлы турниров SQLite-версии сохраняются.

Сетевое обновление **«БД игроков → Обновить БД игроков из интернет»** и импорт используют общее окно. При сетевой загрузке его заголовок — «Обновление базы данных игроков». Оно показывает этап, объём XML в КБ (1024 байта), скорости, прочитанные записи и прошедшее время. Показатели обновляются раз в секунду; текущая скорость рассчитана за последние 2 секунды. При неизвестном размере процент и оценка времени не показываются. Оценка относится к чтению XML; создание индексов, проверка и применение выполняются после него. Прочитанных записей может быть больше, чем уникальных игроков.

Кнопка **«Отмена»**, Esc и крестик отменяют операцию до применения результата. Дождитесь завершения очистки; затем можно повторить попытку. На коротком этапе замены/отката отмена недоступна. Успех отображается после переключения базы и обновления таблицы.

Перед заменой сохраняется комплект DB в `data/Backup/DB-before-import-*`; путь показан после успеха. SQLite копируется штатным механизмом резервирования с учётом WAL и исторических записей. Эти копии автоматически не удаляются.

После прерывания процесса незавершённая замена восстанавливается при следующем запуске до открытия базы. Если копия повреждена или восстановление не удалось, программа сохраняет журнал `data/db-package.pending` и сообщает об ошибке; продолжать работу со смешанным комплектом нельзя. Сохраните журнал, указанную резервную копию и оставшуюся временную папку; устраните ошибку доступа либо восстановите повреждённый файл копии и повторите запуск. Не удаляйте журнал ради обхода защиты и не удаляйте WAL/SHM вручную.

Подробности проверки и ограничения: [BL-11 / BL-13](validation/Проверка-BL-11-и-BL-13.md).

## Дата базы в статусной строке

Во второй панели справа внизу главного окна показана дата установленного каталога. Она сохраняется в data/DB/db.xml и сравнивается с датой публикации на сервере TTW, включая часы, минуты и секунды. При одинаковом показанном календарном дне серверная база всё ещё может быть новее.

Зелёный значок означает, что полученная серверная дата не новее установленной; жёлтый — на сервере есть более новая дата либо локальная дата неизвестна; вопрос — свежесть проверить не удалось. Время скачивания и дата файла Players.sqlite не используются как дата каталога.

В 0.1.10 новое окно не переносило дату из сервиса публикации и не обновляло статус сразу после применения. Исправление описано в [отчёте](validation/Дата-базы-и-статусная-панель.md) и пока не опубликовано. Уже установленной 0.1.10 потребуется исправленная сборка и повторное штатное обновление списка: вручную подменять старую дату текущим временем не следует.


## Меню настройки и информация о базе игроков

Верхнее меню **«Настройка»** содержит пункты **«Общие настройки»** и **«Настройка страницы печати»**.

В меню **«БД игроков → Информация о БД игроков»** показаны полный путь к SQLite-файлу, его размер в Кбайтах (1024 байта) с разделителями разрядов и двумя знаками после запятой, количество текущих игроков без исторических записей и дата/время последнего успешного обновления из интернета по местному времени компьютера. Размер относится к самому SQLite-файлу, без служебных WAL/SHM. Путь и значения можно выделять и копировать.

Время загрузки сохраняется в метаданных SQLite вместе с новой базой и отличается от даты публикации базы в статусной строке. Отмена, ошибка и откат сохраняют прежнее значение. Для старых баз без отметки и после локального импорта отображается «Нет сведений».

Ручной пункт создания резервной копии убран из меню. Автоматические резервные копии перед загрузкой и импортом продолжают создаваться.
