# Сборка в Windows

Эта инструкция предназначена для разработчика. Для запуска готового ZIP-комплекта JDK, Zig и инструменты сборки не нужны; см. [инструкцию пользователя](Руководство-пользователя.md).

## Требования

- Windows и PowerShell. Команды ниже выполняются из корня репозитория.
- JDK 17 или новее; проверенная среда сборки — JDK 25. `-JdkHome` указывает на папку JDK, содержащую `bin/javac.exe`.
- Zig 0.17.1 для сборки Windows EXE. Версия, адрес загрузки и SHA-256 зафиксированы в `config/native-toolchain.json`.
- Интернет для первоначальной загрузки Java-зависимостей. Версии и SHA-256 находятся в `config/dependencies.lock.json`, кеш — в `.cache/dependencies`.
- Для полного комплекта — отдельно подготовленный JRE 25 x64 с файлами лицензий.

Это не полный исходный проект оригинального TTWR. Изменённые классы и новые помощники находятся в исходниках, остальные классы берутся из `vendor/upstream/ttwr.dat`. Оригинальный архив уже включён в репозиторий; сборка сверяет его с lock-файлом. Не подменяйте его ранее собранной SQLite-версией.

Рабочие классы компилируются с `--release 8`, инструменты сборки — с `--release 17`. Собранная программа поддерживает Java 8+ x32/x64; проверенные варианты — Java 8 x32 и Java 25 x64 на Windows x64.

## Собрать программу

Укажите свои пути к установленным инструментам:

```powershell
.\scripts\build.ps1 -JdkHome 'C:\Program Files\Java\jdk-25' -Zig 'C:\Tools\zig\zig.exe'
.\scripts\test.ps1 -JdkHome 'C:\Program Files\Java\jdk-25'
```

Если `zig` есть в PATH, параметр `-Zig` можно опустить. JDK также ищется через `JAVA_HOME`, PATH и стандартный каталог Java, но явный `-JdkHome` делает выбор однозначным.

`build.ps1` загружает и проверяет зависимости, компилирует классы и инструменты с публичной библиотекой ASM, преобразует классы оригинального TTWR и проверяет полученный архив. Затем создаёт пустую стартовую SQLite-базу и собирает x86-запускатель с иконкой.

Результат — `build/image/ttwr-sqlite`:

```text
ttwr-sqlite.exe
app/
  ttwr.dat           программа со встроенной версией
  lib/               библиотеки, включая SQLite JDBC
  seed/              пустая стартовая база: 0 игроков
```

Для пересборки только Java-классов можно добавить `-SkipNative`. Этот режим не пересобирает EXE; перед упаковкой нужен существующий запускатель от полной сборки. После изменения native-кода или ICO выполните полную сборку.

Версия читается из `VERSION` и включается в `app/ttwr.dat` как `ttr/build-version.txt` и `Implementation-Version` манифеста. После изменения `VERSION` пересоберите архив: одна правка имени ZIP версию программы не изменит.

## Подготовить оба ZIP-комплекта

После успешной сборки и проверок:

```powershell
# Использует установленную у пользователя Java 8+ x32/x64
.\scripts\package.ps1

# Включает JRE 25 x64; путь должен содержать bin/java.exe и лицензии
.\scripts\package.ps1 -RuntimeHome 'C:\Tools\temurin-jre-25'
```

Для версии `X.Y.Z` создаются:

| Комплект | Папка | Архив |
|---|---|---|
| Без Java | `dist/ttwr-sqlite-X.Y.Z-system-java` | `releases/ttwr-sqlite-X.Y.Z-system-java.zip` |
| С Java x64 | `dist/ttwr-sqlite-X.Y.Z-windows-x64` | `releases/ttwr-sqlite-X.Y.Z-windows-x64.zip` |

Каждый комплект содержит `checksums.json` с размером и SHA-256 файлов. Хеши ZIP добавляются в `releases/SHA256SUMS.txt`. В комплект копируются программа, библиотеки, стартовая база, документация, значки и сведения о лицензиях; рабочая `data` не включается.

После подготовки обоих ZIP проверьте их с установленной Java 8 x32:

```powershell
.\scripts\verify-packages.ps1 -Java32Home 'C:\Tools\jre8-x32'
```

Проверка распаковывает отдельные копии и проверяет манифест, версию, пустую стартовую базу и запуск. Подробности — в [инструкции по тестированию](Тестирование.md).

## Повторная сборка и сохранность данных

- Не запускайте рабочую программу в `build/image`: при наличии там `data` сборка остановится, чтобы сохранить профиль.
- `package.ps1` отказывается заменять существующую папку результата или ZIP. Параметр `-OutputDirectory` меняет только папку комплекта; имя ZIP по-прежнему определяется `VERSION`.
- Для повторного пробного пакета используйте отдельную копию репозитория без старых результатов. Для нового опубликованного выпуска назначьте новую версию.
- Не удаляйте `data`, базы и настройки ради успешной сборки. Не включайте их в Git или ZIP.

Java-зависимости загружает `scripts/fetch-dependencies.ps1`. При ошибке SHA-256 проверьте файл и источник загрузки; не отключайте проверку. При изменении иконок используйте `scripts/generate-icons.py`; обычная сборка использует готовые PNG/ICO из `assets`. Для генерации нужна необязательная зависимость `resvg-py`, см. `assets/README.md` в исходном проекте.

## Публикация

Перед коммитом выполните `scripts/check-public-tree.ps1`: локальные сборки, кеш, профили и журналы должны оставаться вне Git. Для `vendor/upstream/ttwr.dat` предусмотрено отдельное исключение как для входного архива сборки.

Порядок автоматической сборки и выпуска: [GitHub Actions](https://github.com/uranic2/ttwr-sqlite/blob/main/docs/Автоматическая-сборка-и-публикация.md). Сведения о сторонних компонентах и лицензиях — в `THIRD_PARTY_NOTICES.md`.
