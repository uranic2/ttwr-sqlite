# TTWR SQLite

Модифицированная Windows-версия клиентской программы TTWR со списком игроков в SQLite и отдельной переносимой папкой данных.
Программы TTWR предназначена для проведения турниров по настольному теннису и их обсчета в рейтинге TTW.

Текущая версия: **0.1.11**.

## Скачать версию 0.1.11

- [Со встроенной Java 25 x64 — Windows x64](https://github.com/uranic2/ttwr-sqlite/releases/download/v0.1.11/ttwr-sqlite-0.1.11-windows-x64.zip). Устанавливать Java отдельно не требуется.
- [Без встроенной Java](https://github.com/uranic2/ttwr-sqlite/releases/download/v0.1.11/ttwr-sqlite-0.1.11-system-java.zip). Нужна установленная Java 8 или новее, x32 либо x64.

[Описание релиза 0.1.11](https://github.com/uranic2/ttwr-sqlite/releases/tag/v0.1.11). 



## Запуск программы

1. Распакуйте ZIP-комплект целиком, 
2. Запустите `ttwr-sqlite.exe`, 
3. Затем выберите **«БД игроков → Обновить БД игроков из интернет → Обновить»**. Стартовая база содержит 0 игроков.

Комплект `windows-x64` включает Java 25 x64. Комплект `system-java` использует установленную Java на компьютере. Папка `app` обязательна; `runtime` необязательна. Переносите папку `data` вместе с программой, чтобы сохранить свои данные.

## Что такое TTW-Рейтинг

TTW-Рейтинг — система оценки уровня игроков в настольный теннис по результатам турниров. В основе расчёта — формула ФНТР с учётом рейтингов соперников и коэффициента турнира, зависящего от среднего рейтинга участников. Рейтинг помогает сравнивать силу игроков, проводить посев и отслеживать прогресс.

Подробнее: [TTW-Рейтинг на сайте TTW](https://r.ttw.ru/ttw-rating/).

## В чем проблема исходной программы

Исходная программа хранит список всех игроков, когда-либо участвовавших в турнирах, в XML-файле `Players.xml`. При каждом старте весь список парсился и загружался в память через DOM. На списке примерно из 150 тысяч игроков это проявлялось в очень долгом запуске и большом потреблении памяти. При сохранении программа заново формировала и переписывала весь XML, даже если изменялась лишь небольшая часть данных. Некоторые пользователи сообщали о 20 минутах ожидания, пока запустится программа.

Подробнее: [проблемы исходной программы](docs/Исследование-производительности.md).

## Основные изменения TTWR SQLite

- База игроков Players.xml перенесена в базу SQLite.

- База и настройки храниться в папке `data` рядом с `ttwr-sqlite.exe`, без использования профиля старого TTWR в AppData.

- Поиск, фильтры, сортировка и выбор игроков из SQLite, страницы по 100 записей.

- Пустая стартовая база; загрузка списка игроков происходит штатным образом через скачивание XML и далее обновление базы.

- Есть встроенная Java. Она имеет приоритет при запуске; без `runtime` запускатель находит Java 8+ x32 или x64.

- Программа опубликована на [GitHub](https://github.com/uranic2/ttwr-sqlite). Проверка и установка обновлений доступны через меню **«Справка → Проверить обновления программы…»**.



Подробности: [Руководство пользователя](docs/Руководство-пользователя.md), [полный список изменений](CHANGELOG.md), [Как работает обновление из программы](docs/Обновление-программы.md)

## Структура проекта

```text
src/main/java/       изменения Java-программы и помощники XML/SQLite
src/main/native/     исходник Windows-запускателя
src/test/java/       проверки на синтетических данных
src/test/native/     проверки ошибок поиска Java
tools/java/          сборка и изменение байткода исходного TTWR
scripts/             загрузка зависимостей, сборка, проверки, упаковка
config/              версии и SHA-256 зависимостей
docs/                архитектура, изменения, сборка и результаты проверок
vendor/upstream/     оригинальный ttwr.dat для сборки; 
build/               промежуточные файлы; 
dist/                готовая программа;
releases/            ZIP-комплекты;
```



## Отказ от ответственности и мотивация автора

Используйте программу на свой страх и риск.

Я не Java-разработчик: код и большая часть документации написаны с помощью ИИ. У меня нет документации на оригинальную TTWR, и сам я не использую её для проведения турниров и отправки результатов в TTW. Поэтому полноценно проверить этот сценарий я не могу. Последние четыре года я отправляю результаты в RTTF.

Ещё около пяти лет назад я предлагал переписать TTWR: уже тогда была понятна проблема хранения и обработки  базы игроков. Несколько раз я писал об этом и в публичном чате TTWR.

10 ноября 2026 года, снова прочитав жалобы на долгий запуск, я ради интереса, попросил Codex переработать хранение списка игроков: перенести его из XML в SQLite и отказаться от загрузки всего списка через DOM. Получившийся результат стал основой этой модификации.

Для меня это был больше эксперимент по работе с ИИ:

"Смогу ли я поправить программу, на совершенно незнакомой мне JAVA и не имея исходных кодов."

Оказалось что это возможно.



## Дальнейшее развитие программы

Для сообщений об ошибках и конкретных предложений используйте [Issues](https://github.com/uranic2/ttwr-sqlite/issues), а для вопросов и обмена мнениями — [Discussions](https://github.com/uranic2/ttwr-sqlite/discussions). В сообщении об ошибке укажите версию программы, шаги воспроизведения, ожидаемый и фактический результат. Это поможет разобраться в проблеме.

При этом, я не вижу большого смысла в масштабном развитии клиентской TTWR на существующем технологическом стеке. Кроме того, изменения на стороне TTW могут повлиять на совместимость отправки результатов. 

Осенью 2026 года, впервые за долгое время, появились признаки обновления TTW, в том числе и новая версия сайта с рейтингом. Это обнадёживает, но, на мой взгляд, за предыдущие годы RTTF ушёл далеко вперёд по возможностям и удобству. Я скептически отношусь к тому, что команда TTW сможет предложить нечто более лучшее, особенно на полностью бесплатной основе.

В долгосрочной перспективе любому такому сервису нужны средства:

- на серверы, доменные имена и необходимые сертификаты;
- на администрирование: обслуживание базы, объединение дублей игроков и исправление явных ошибок в результатах;
- на резервное копирование, контроль работы сервиса и своевременное продление доменных имен, сертификатов.

Если для этого придётся собирать деньги с пользователей, то бесплатность перестанет быть отличием от RTTF (К слову, у RTTF тоже есть бесплатная опция - но будет задержка с публикацией результатов в два дня).
